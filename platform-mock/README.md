ไม่มีลิงก์ไปที่ CDN หรือฟอนต์ภายนอกเลย ทุกอย่าง (CSS + JS + ข้อมูลตัวอย่าง) อยู่ในไฟล์เดียว

## นี่คืออะไร

ภาพจำลองหน้าจอ (visualisation prototype) ของ **แพลตฟอร์มงานสำนักงานบัญชี KSK** ตามแบบที่อนุมัติแล้วใน
`firstmate/data/ksk-console-platform-design/report.md` และมติของกัปตันวันที่ 3 ส.ค. 2569
(`captain-decisions-2026-08-03.md`)

มีไว้เพื่อ **เดินดูทั้งระบบแล้วเถียงกับมันได้** ก่อนจะลงมือเขียนของจริง — เมนู หน้าจอ ลำดับการทำงาน
สิทธิ์ของแต่ละบทบาท และสิ่งที่ผู้ใช้จะเห็นจริง ๆ

## นี่ไม่ใช่อะไร

- **ไม่ใช่ระบบจริง** — ไม่มีฐานข้อมูล ไม่มี backend ไม่มีการล็อกอินจริง (ไม่ตรวจรหัสผ่าน)
- **ไม่บันทึกอะไรทั้งสิ้น** — สิ่งที่กดแก้จะอยู่แค่ในหน่วยความจำของแท็บ รีเฟรชแล้วกลับสู่ค่าเริ่มต้น
- **ไม่เรียกสายคีย์เอกสารจริง** — ปุ่ม “เริ่มรอบคีย์เอกสาร” เป็นการจำลองล้วน ๆ ไม่มีค่าใช้จ่ายเกิดขึ้น
- **ข้อมูลลูกค้าเป็นข้อมูลสมมติ** — ชื่อบริษัท/รหัส/ค่าบริการอิงจาก mockup ของลูกค้าเพื่อความสมจริง
  แต่ที่อยู่ เบอร์โทร อีเมล เลขผู้เสียภาษี LINE group id และตัวเลขทั้งหมดถูกแต่งขึ้น
- **ไม่ใช่โค้ดที่จะเอาไปใช้ต่อ** — โครงสร้างไฟล์นี้เขียนให้ดูง่าย ไม่ได้เขียนให้ต่อยอดเป็นของจริง

## จะดูอะไรก่อนดี

หน้าแรกหลังล็อกอินมีการ์ด **“ลองกดดู 8 อย่างนี้”** ที่พาไปยังจุดที่ตั้งใจให้ดูโดยเฉพาะ เช่น
กฎสี่ข้อของการเซ็นผ่านด่าน, การยิง API เปลี่ยนสถานะด่าน, ตัวออกแบบแม่แบบด่าน และจุดที่สายคีย์เอกสาร
มาบรรจบกับด่าน 2

**สลับบทบาทได้ที่ชิปชื่อผู้ใช้มุมขวาบน** — เมนู ปุ่ม และสิทธิ์เซ็นจะเปลี่ยนตามบทบาทจริง
(ผู้ดูแลระบบ / ผู้บริหาร / หัวหน้าทีม / รองหัวหน้า / พนักงาน / นศ.ฝึกงาน / ทีมรับเอกสาร)

## หน้าจอในตัวอย่างนี้ กับเฟสของแผน

ทุกหน้ามีป้าย “เฟส n” บอกว่าตามแผนใน report.md §9 หน้านั้นจะมาถึงเมื่อไหร่
(กดปุ่ม “ดูคำอธิบายป้ายเฟส” ที่ท้ายเมนูซ้ายเพื่อดูความหมายของทุกเฟส)

| หน้า | เฟส |
|---|---|
| ล็อกอิน (อีเมล + รหัสผ่าน) และเปลือกระบบ + สลับบทบาท | 1 |
| กระดานงานเดือน (รวมตารางด่านแบบ matrix) | 1 |
| ลูกค้า & บริการ + หน้าลูกค้ารายตัว (ผู้ติดต่อ, บริการ, LINE group id) | 1 |
| ผู้ใช้ & ทีม + ตารางสิทธิ์ | 1 |
| งานประจำงวด: ด่าน, checklist, หลักฐาน, การเซ็น, ประวัติกิจกรรม | 2 |
| แม่แบบด่านงาน + **ตัวออกแบบด่าน** (เวอร์ชัน/ร่าง/เผยแพร่) | 2 |
| บันทึกกิจกรรม (audit) | 2 |
| ข้อยกเว้น & กำหนดส่ง + การเร่งงานตาม SOP | 3 |
| รอบคีย์เอกสาร + ตัวกระทบยอดโฟลเดอร์ | 4 |
| รายงาน & ภาระงาน | 5 |
| เก็บเงินลูกค้า (โครงเปล่า ตั้งใจไม่เดาเนื้อหา) | 6 |
| ระบบ, API & สำรองข้อมูล (Cloudflare R2, ผู้เรียกผ่าน API) | 0 |

## มติของกัปตันที่ตัวอย่างนี้แสดงให้เห็น

1. ล็อกอินด้วย **อีเมล + รหัสผ่าน** ทุกบทบาท ไม่มีหน้าจอ PIN
2. **แพลตฟอร์มคือแหล่งความจริง** — ไม่มี Airtable โผล่ที่ไหนในระบบ
3. **ด่านไม่ผ่านเอง** แต่ **ผู้เรียกผ่าน API เปลี่ยนสถานะด่านได้** และปรากฏใน timeline เป็น actor
   ของตัวเอง (สีม่วง กรอบประ ไอคอนเฟือง) แยกจากมนุษย์ชัดเจน
4. **นศ.ฝึกงานเริ่มรอบคีย์เอกสารได้** แต่เซ็นผ่านด่านไม่ได้
5. **สำรองข้อมูลขึ้น Cloudflare R2 ทุกวัน** — ดูสถานะได้ในหน้าผู้ดูแลระบบ · เอกสารต้นฉบับยังอยู่ Dropbox
6. **เก็บ LINE group id** เป็นข้อมูลจริงต่อลูกค้า แต่ยังไม่มีฟีเจอร์ส่งข้อความ
7. **ไม่มีการวิเคราะห์งบการเงินด้วย AI** — ตัดออกจากขอบเขต
8. **ผู้ดูแลออกแบบเฟสและด่านเองได้** — ตัวออกแบบเป็นหน้าจอจริงในตัวอย่างนี้ ไม่ใช่ปุ่มหลอก
