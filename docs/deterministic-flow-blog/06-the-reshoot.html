บทที่ 6 — การปรับปรุง

วันที่ปั้นหน้าตาทั้งเว็บใหม่

25 กรกฎาคม 2569 — สิบ commit รวดในวันเดียว ที่เปลี่ยนหน้ารีวิวทุกหน้าให้เป็น 3-pane พร้อม PDF.js จริง

หลัง #41/#42 วางโครงข้อมูลไว้แล้ว วันที่ 25 กรกฎาคมกลายเป็นวันปรับหน้าตา (visual rework) ล้วนๆ — ไม่ใช่ฟีเจอร์ใหม่ แต่เป็นการทำให้หน้าที่มีอยู่ใช้งานได้จริงบนหน้าจอจริง สิบ commit ในวันเดียวไล่กันดังนี้:

commitสิ่งที่เปลี่ยน
581e77cรื้อหน้ารีวิวเอกสารเป็น layout 3-pane + PDF.js viewer
4120f0dรื้อหน้ารีวิวตัดออกเป็น full-bleed compare + PDF.js แบบ pin ไว้
4a9ce24เพิ่ม breadcrumb header ทุกหน้ารีวิว
bf16777ทำหน้ารีวิวหลักเป็น work queue ที่มีตัวเลขจริง ไม่ใช่แค่ลิงก์
cedec57บันทึกแล้วเลื่อนไปเอกสารถัดไปเอง พร้อมประกาศเมื่อครบ

5384f27หน้ารีวิวรายการเดินบัญชีธนาคาร split-view พร้อม PDF.js preview

f522ba5rebuild ข้อมูลรีวิวทุกกลุ่ม พร้อมสืบทอดการแก้ไขของมนุษย์ไปด้วย
97675e5เมนู ⋯ ต่อเดือน บน dashboard ที่ rebuild ข้อมูลรีวิวแบบถูกๆ

ทำไม "แค่หน้าตา" ถึงกินไปทั้งวัน

เพราะมันไม่ใช่แค่ CSS — งานรีวิวเอกสารบัญชีต้องการดูภาพต้นฉบับ (สลิป ใบกำกับภาษี รายการเดินบัญชี) คู่กับข้อมูลที่ตีความออกมาพร้อมกันตลอดเวลา หน้าจอที่มีแค่ลิงก์เปิดแท็บใหม่ทีละไฟล์ใช้งานจริงไม่ได้ เมื่อต้องเทียบเอกสารหลายร้อยชิ้นต่อเดือน — PDF.js ที่ pin ไว้ในหนึ่งใน pane บวกกับ layout 3 ช่อง (breadcrumb, viewer, ฟอร์มแก้ไข) คือสิ่งที่ทำให้หน้าเหล่านี้ใช้งานได้จริงในเวิร์กโฟลว์ต่อเนื่อง

commit bf16777 เปลี่ยนหน้ารีวิวหลักจากลิสต์ลิงก์เฉยๆ ให้กลายเป็น "คิวงานที่ปิดประตูได้จริง" (gated work queue) — มีตัวเลขจริงกำกับว่าเหลืออีกกี่รายการ ไม่ใช่แค่โครงหน้าเปล่า และ cedec57 ปิดวงจรด้วยการเลื่อนไปเอกสารถัดไปอัตโนมัติหลังบันทึก พร้อมประกาศเมื่อคิวหมด — ลดจำนวนคลิกต่อเอกสารลง ในงานที่ต้องทำซ้ำเป็นร้อยรอบต่อเดือน

เมนู ⋯ กับปัญหาที่ตามมาทันที

97675e5 เพิ่มเมนู ⋯ ต่อเดือนบนแดชบอร์ด ให้สั่ง rebuild ข้อมูลรีวิวได้แบบถูกๆ (ไม่ต้องรัน pipeline ใหม่ทั้งชุด) พ่วงมากับ f522ba5 ที่ทำให้การ rebuild นั้น "สืบทอด" การแก้ไขของมนุษย์ ที่เคยทำไว้ต่อกลุ่มไปด้วย ไม่ใช่ล้างทิ้งกลับไปเป็นค่า AI เดิม

บั๊กที่ตามมาในวันถัดไป

65b17d5 — เมนู ⋯ ที่เพิ่งสร้างถูกตารางบัง (clipped) เพราะ overflow ของแถวตาราง ตัด dropdown ที่ควรจะลอยทับอยู่ข้างบน แก้ด้วยการจัดการ stacking/overflow context ใหม่ — เคสคลาสสิกของ UI ที่ทดสอบผ่านตอนสร้าง แต่โผล่บั๊กจริงทันทีที่ใช้งานในตารางที่มีแถวเยอะขึ้น
