บทที่ 8 — บทสรุป

อินเทอร์เฟซที่ยืนอยู่วันนี้

ทัวร์สั้นๆ ของสิ่งที่สร้างเสร็จแล้ว เทียบกับของเก่าที่ถูกแทนที่ และสิ่งที่ยังไม่ถูกแตะ

ปรับปรุงหลังบทนี้ถูกเขียน — 3 ส.ค. 2026

ตอนที่บทนี้เขียนขึ้น โฟลเดอร์ console/ มีเว็บแอป สองตัว อยู่ซ้อนกัน และบทนี้บรรยายทั้งสองตัวปนกันโดยไม่ได้แยกให้ชัด — ตัวเก่า (console/server.ts, กระดาน 3 เลนของบทที่ 4) กับตัวใหม่ที่ขับด้วย sequencer (console/app/) ตัวเก่าถูกลบออกไปแล้วทั้งหมด เนื้อหาด้านล่างนี้แก้ให้ตรงกับสิ่งที่เหลืออยู่จริง

console/ วันนี้คือเว็บแอปตัวเดียว รันด้วย bun run app/server.ts มันไม่ได้ห่อ /ksk-keying ทั้งเส้นไว้ในรันเดียว แต่สั่ง claude -p ทีละ stage ตาม sequencer แล้วเอาผลของแต่ละ stage มาขึ้นเป็นหน้าตรวจทาน — ไม่มีระบบล็อกอินของตัวเอง รันตรงบนเครื่องจะ bind 127.0.0.1, ส่วน deployment จริงบน Docker bind 0.0.0.0 โดยมี Cloudflare Access (allowlist อีเมล) เป็นด่านเดียวที่กั้นอยู่

ไม่มี mock mode

ทุก stage spawn binary claude จริงเสมอ — ไม่มีโหมดจำลองให้กดเล่นฟรี ดังนั้น KSK_WORKSPACE_ROOT จึงเป็นค่าบังคับ เซิร์ฟเวอร์ตรวจตั้งแต่ boot และ exit(1) ทันทีถ้าไม่ได้ตั้งหรือชี้ไปยังโฟลเดอร์ที่ไม่มีอยู่จริง แทนที่จะเดาค่า default ให้ (mock engine เป็นของ console ตัวเก่า และถูกลบไปพร้อมกัน)

โครงสร้างหน้าจอ

  • แดชบอร์ด — ลูกค้าเป็นหัวข้อ เดือนเป็นแถว บอกสถานะ ปริมาณงาน เวลาโดยประมาณ และปุ่มสั่งงานต่อเดือน (บทที่ 4)
  • หน้ารีวิวตัดออก/ซ้ำ — split-view + PDF.js, แก้คืนได้ผ่าน repair loop (บทที่ 5)
  • หน้ารีวิวหมวดหมู่/กลุ่มเอกสาร + รายการเดินบัญชี — 3-pane, บันทึกแล้วเลื่อนอัตโนมัติ, ปุ่มส่งออก PEAK XLSX ต่อ bucket (บทที่ 5–6)
  • ไดอะล็อกเรียนรู้ (🎓 เรียนรู้จากการแก้ไข) — ในเมนู ⋯ ต่อเดือนบนแดชบอร์ด, แสดงข้อเสนอ + บันทึกที่ค้างอยู่ (บทที่ 7)

สิ่งที่ถูกแทนที่จริง

ของเดิมสถานะวันนี้
ตรวจทาน HTML ที่ pipeline เขียนลงโฟลเดอร์ลูกค้าโดยตรง (file://)เลิกใช้ในเส้นทางใหม่ — ทุก artifact เป็น YAML/JSON, console render หน้ารีวิวเองแบบ server-rendered
Vue console + SQLite (สคีมา ksk_review_human_state.v1, ADR 0002)ไม่ถูกใช้ต่อ — เอกสารเก่าคงไว้เป็นบันทึกประวัติศาสตร์เท่านั้น ตามที่ issue #1 ระบุไว้ตอนปิด
ฟีเจอร์ resume ด้วยข้อความอิสระถูกถอดทิ้งทั้งหมด — ไม่มี free-text input ที่ไหนในหน้าจอ, ทางเดียวไปต่อคือ "เริ่มใหม่"
learning-notes.md ที่เขียนได้แต่ไม่มีใครอ่านปิดวงจรแล้วโดย #47 — มนุษย์เคลียร์ได้, ksk-magnum อ่านตอนรับลูกค้าใหม่
console ตัวเก่า (console/server.ts + engine.ts + mock engine + กระดาน 3 เลน, พอร์ต 4820)ลบออกทั้งหมดเมื่อ 3 ส.ค. 2026 — ตัวใหม่ไม่เคย import อะไรจากมันเลย ผูกกันทางเดียวคือตัวเก่าเรียกใช้ sequencer/process-supervisor.ts ซึ่งเป็นของตัวใหม่อยู่แล้ว

ผลกระทบต่อ codebase เดิม

การเปลี่ยนแปลงทั้งหมดอยู่ในขอบเขต console/ เกือบทั้งหมด — pipeline หลักของ /ksk-keying เอง (agent roster: watson, marple, sherlock, poirot, lestrade, magnum และ stage skill ต่างๆ) แทบไม่ถูกแตะ มีเพียงจุดเชื่อมต่อที่จำเป็น: stage-shape-check.ts ใหม่ในโฟลเดอร์สคริปต์ของ skill, และการแก้ field name ใน learn.ts (สคริปต์ฝั่ง skill) ให้ตรงกับ contract ของ changelog — codebase เก่าที่เคยพึ่ง Vue console + SQLite (ADR 0002, events taxonomy) ถูกปล่อยไว้เป็นซาก ไม่ถูกลบทิ้งทันที แต่ก็ไม่มีเส้นทางไหนอ้างอิงมันอีก

สิ่งที่ยังไม่ได้ทำ

แผนที่ #29 ปิดครบตามที่เขียนไว้ ("destination reached") แต่ตัวแผนที่เองก็ไม่ได้อ้างว่าเป็นจุดจบสุดท้าย ของทั้งระบบ — เพดานงบประมาณ, Range/206 บน /files/, การขยายจาก single-user เป็น multi-user ล้วนเป็นพื้นที่ที่ถูกทิ้งไว้ตั้งใจ ("deferred until real pain") ไม่ใช่สิ่งที่ลืม

หกวัน จากวันที่ตัดสินใจทิ้งของที่เพิ่งสร้างเสร็จ ถึงวันที่วงจรการเรียนรู้ปิดสนิท — นี่คือระยะทางทั้งหมด ที่ worktree deterministic-flow เดินผ่านมา
