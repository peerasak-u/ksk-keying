บทที่ 2 — การออกแบบ

แผนที่ชื่อ #29 กับกติกาที่วางไว้ก่อนแตะโค้ด

ก่อนจะมีบรรทัดโค้ดเดียว ทุกคำถามใหญ่ถูกถามและตอบไว้แล้วบนกระดาน — กรอบเว็บ, โมเดล concurrency, แม้แต่การจัดลำดับหน้ารีวิว

เป้าหมายที่เขียนไว้บนแผนที่ #29 สั้นและตรง: เว็บแอปตัวเดียวจากศูนย์ที่ขับเคลื่อน sequencer แบบกำหนดขั้นตอนตายตัว (deterministic per-stage) ให้ครบวงจร — เลือกบริษัท/เดือน มีประวัติการรัน มีแดชบอร์ดสด รีวิวข้ามหรือตัดออกก่อน แล้วค่อยรีวิวหมวดหมู่/กลุ่มเอกสาร จบด้วย PEAK export — และทุกการแก้ไขของมนุษย์ต้องเก็บเป็น artifact ของมันเอง ที่ภายหลังจะมี pass การเรียนรู้ดึงกลับไปสอน coa_usage.json

สิ่งที่ทำให้แผนที่ใบนี้ต่างจากงานออกแบบทั่วไปคือ มันแตกเป็น ticket ย่อยที่ตัดสินใจก่อนสร้าง แล้วเก็บผลสรุปไว้บนตัว issue เอง กลายเป็นเอกสารตัดสินใจแบบ living document ที่ตั๋วสร้างจริงอ้างอิงกลับมา

กรอบเว็บ: ไม่มีกรอบ

Issue #30 ให้คะแนนตัวเลือกกรอบเว็บทั้งหมดแบบตรงไปตรงมา: Bun.serve() เปล่าๆ ไม่มีกรอบ ได้ 9/10, htmx 8.5, Elysia 6, Hono 5.5, SvelteKit 4, Next.js 3 — เลือก Bun.serve() เพราะตรงกับ รูปแบบ zero-dependency ที่ console/server.ts เดิมทำอยู่แล้ว แค่ขยายให้ครอบคลุมหน้า document review แบบ server-rendered แทนที่จะเป็น static HTML แบบ file://

Concurrency: คิวเดียว ทั่วทั้งระบบ

Issue #31 ล็อกโมเดลไว้ตั้งแต่ต้น: limit concurrency ที่ตั้งค่าได้ (default 1 — คือ FIFO ทั่วระบบโดยพฤตินัย), sequencer loop รันเป็น async task อยู่ใน process เดียวกับ Bun.serve() (ไม่ spawn child process แยกต่อการรัน), run state ถูก persist เป็น YAML อยู่ในโฟลเดอร์ ข้อมูลระบบ ของลูกค้าแต่ละเดือนเอง, และสถานะสดส่งผ่าน SSE

Prototype ก่อนของจริง

แผนที่นี้อนุญาตให้มี ticket "Prototype" แยกจาก "Build" — สร้างเพื่อทดสอบไอเดีย เก็บไว้ใน console/_prototype_*/ โดยไม่ต้อง promote ทันที จนกว่าจะมี build ticket จริงมารองรับ สองอันที่สำคัญ:

  • #32 — หน้าเลือกบริษัท/เดือน + แดชบอร์ด: เทียบ 3 ทางเลือกออกแบบ (ตารางเดียวจัดกลุ่มตามลูกค้า vs. การ์ดบริษัท+แถวงานที่กำลังทำ vs. Kanban+ตัวเลือกด่วน) ผ่าน feedback 3 รอบ ก่อนล็อกตัวเลือกแรก
  • #34 — หน้ารีวิวตัดออก/ข้าม: จอแบ่งครึ่งเต็มความสูง ฝั่งซ้ายเป็น document viewer เต็มจอ (สอง panel เคียงกันเมื่อเป็นเคส "หน้าที่ตัดออก" / "หน้าที่ซ้ำอยู่ (เก็บไว้)"), ฝั่งขวาเป็นลิสต์คำกล่าวอ้างที่เลื่อนได้ คลิกแถวแล้วโหลดเข้า viewer ตัดสินใจแล้วเลื่อนไปข้อถัดไปเอง

กติกาที่ล็อกไว้และไม่ยอมเปิดใหม่

"The PEAK export file format itself is an external, fixed target — not open for redesign." ประโยคนี้ในตัวแผนที่ตัดปัญหาที่มักวนซ้ำในงานบัญชี — รูปแบบไฟล์ export ที่ต้องตรงกับระบบ PEAK ภายนอกเป๊ะ ถูกประกาศเป็นข้อเท็จจริงคงที่ ไม่ใช่พื้นที่ให้ถกเถียงออกแบบใหม่อีก
